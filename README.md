# פרוייקט שבוע 14

## ניתוח המערכת 

### הבעיה 

יחידת רחפנים צבאית מקבלת מדי יום קובץ נתונים גולמי ממערכת חיישנים חיצונית. הקובץ מכיל מידע על כמאה
רחפנים הפועלים בבסיסים שונים ברחבי הארץ. המערכת החיצונית אינה אמינה לחלוטין: המבנה הכללי של הקובץ
תקין מבחינה תחבירית וניתן לקריאה, אך חלק מהרשומות מכילות ערכים שאינם עומדים בתקני היחידה

### עבור מי 

צוות בקרת האיכות דורש מערכת שתבצע תהליך עיבוד נתונים אוטומטי: קליטת הנתונים הגולמיים, בדיקת תקינותם,
יצירת מאגר נתונים נקי, ביצוע ניתוחים סטטיסטיים והפקת דוח מסכם

### איך נראית הצלחה?

המערכת נדרשת לבחון את הרשומות ולשמור את המידע המאושר בקובץ json.clean_drones, מבלי לשנות את
המקור הגולמי. הקובץ הנקי משמש כמקור הרשמי לניתוח מצב הצי, חישוב נתונים והפקת דוחות. פעולות הניתוח מתבססות על תוכן json.clean_drones כפי שנקרא מהקובץ שנוצר, ולא על הנתונים הגולמיים.
שגיאה ברשומה בודדת אינה מעידה שכל קובץ הנתונים אינו שמיש. המערכת נדרשת למנוע מהרשומה הבעייתית
להיכלל במאגר המאושר, תוך שמירה על האפשרות לעבד את שאר הרשומות

### תרחיש הכשל של פגיעה באמינות

כאשר קיימת שגיאה בקריאת הקובץ ואין תיעוד מדוייק שמאפשר להבין מה בדיוק קרה.

## פירוק הבעיה לרכיבים 

* **IDataSource (Interface):** מהווה את שכבת ההפשטה לקליטת הנתונים. הממשק מגדיר את המתודה `LoadData()` שכל מקור נתונים עתידי (JSON, SQL, API) חייב לממש. 
* **תקשורת:** שאר רכיבי המערכת תלויים בממשק `IDataSource` ולא במימוש הספציפי שלו, מה שמאפשר הפרדת רשויות מוחלטת (Decoupling).
